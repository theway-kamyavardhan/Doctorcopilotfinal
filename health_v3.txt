# DoctorCopilot: Complete Mobile Design System (v3)

This document is the absolute source of truth for the mobile implementation of DoctorCopilot. It establishes the final design system, strict performance guardrails, and structural rules required to maintain a premium, zero-guesswork native experience.

---

## 1. Product Overview

DoctorCopilot is an advanced, dual-sided healthcare intelligence platform designed to bridge the gap between patient data and clinical analysis. It leverages AI to transform complex medical reports and longitudinal health data into actionable, easy-to-understand insights.

**Core Audiences:**
*   **Patients:** Individuals seeking to understand their health trajectory, manage medical records, and communicate effectively with their healthcare providers.
*   **Doctors:** Clinical professionals needing rapid, AI-assisted digestion of patient history, anomaly detection, and streamlined case management.

---

## 2. System Architecture

*   **Desktop vs. Mobile Rendering Separation:** Strict branching via `useViewport` hook. Desktop receives `LiquidEther`, WebGL, and `recharts`. Mobile receives `MobileSparkline` and native swipe carousels.
*   **Key Technologies:** React, Vite, Tailwind CSS, Framer Motion (micro-animations), custom SVG engines.
*   **Performance Philosophy:** "60fps everywhere." Mobile leans entirely on `content-visibility: auto`, `tabular-nums`, and pure SVG curves.

---

## 5. Mobile Experience (Current State)

*   **Landing / Login:** Functional, lacking seamless biometric/native integration feel.
*   **Patient Dashboard:** Uses `MobileSparkline` SVGs. Metrics arranged in horizontal snap-scroll carousels.
*   **Doctor Dashboard:** Horizontal scroll of KPI cards. Case lists are clean, prioritizing urgent alerts.

---

## 6. Core Problems Solved

1.  **Responsive Web Feel:** Eradicated by enforcing safe-area insets and native scrolling.
2.  **Weak Visual Hierarchy:** Fixed by enforcing Value > Label > Trend > Chart on all cards.
3.  **Flat Charts:** Solved via SVG gradient strokes, area fills, and draw-in animations.
4.  **Limited Interaction Depth:** Solved via `.active-feedback` spring physics.
5.  **Deficient Emotional Design:** Solved via soft neutrals and pure surfaces.

## 10. Design Philosophy Going Forward

*   **Mobile-First Thinking:** Design for the thumb. Redesign core intents for the phone.
*   **Native Feel Over Visual Complexity:** Reject complex backgrounds or blurs. Rely on pure surfaces and fluid motion.
*   **Performance Over Decoration:** 60fps is non-negotiable.
*   **Clarity Over Density:** A user should understand a screen in < 1 second.

## 12. Screen Blueprints (CRITICAL)

### Landing (Mobile)
*   **Layout Structure:** Full-screen Hero → Value Props → Sticky Footer.
*   **Spacing:** Top padding `pt-16`. `p-6` for internal text blocks.
*   **CTA Placement:** Fixed at bottom safe-area (`pb-[env(safe-area-inset-bottom)]`). Always accessible.
*   **Visual Hierarchy:** Large H1 (`text-4xl`, tracking-tight) > Muted Subtitle > Primary Action Button.

### Login (Mobile)
*   **Input Layout:** Stacked inputs. Background `#E5E5EA` (Light) or `#1C1C1E` (Dark). No heavy borders.
*   **Role Selection UI:** Horizontal segmented control.
*   **Button Placement:** Immediately below inputs `mt-8`.

### Patient Dashboard (Mobile)
*   **Order of Sections:** Header (Greeting) → Key Metrics (Health Score) → Priority Signals (Alerts) → Trends Carousel.
*   **Card Layout Structure:** `flex overflow-x-auto snap-x snap-mandatory gap-4 pb-2 -mx-4 px-4 hide-scrollbar`.
*   **Chart Placement:** Bottom 40% of the metric card, overflowing the card padding (`-mx-1`) for a seamless bleed effect.

### Doctor Dashboard (Mobile)
*   **KPI Arrangement:** Horizontal snap-scroll carousel. Order: Total Cases → Open Cases → Pending Review → Alerts.
*   **Alert Priority Layout:** Red/Orange tinted cards immediately below KPIs. "Needs Review" list items feature prominent right-aligned notification dots.
*   **Case List Structure:** Clean list with `divide-y`. High contrast patient name, muted subtext for last updated time.

## 13. Component System

### Metric Card
*   **Layout Structure:** Stacked. Value (Top) → Label (Middle) → Trend Arrow (Middle-right) → Sparkline (Bottom).
*   **Typography Sizes:**
    *   Primary Value: `text-[32px] leading-none font-bold tabular-nums`.
    *   Label: `text-[13px] font-semibold text-gray-500`.
    *   Trend Indicator: `text-[12px] font-bold`.
*   **Spacing Rules:** `p-5` padding. `rounded-[1.5rem]` (24px) border radius.

### Sparkline (`MobileSparkline.jsx`)
*   **Stroke Style:** Linear gradient. Opacity 0.5 → 1.0. `strokeWidth={3}`.
*   **Fill Style:** Linear gradient. Opacity 0.25 → 0.0.
*   **Animation Behavior:** CSS `@keyframes` on `stroke-dashoffset` over 800ms `ease-out`.

### Section Container
*   **Padding:** Container margins `mb-8`. Internal padding `px-4`.
*   **Header Style:** `text-xl font-bold mb-3 px-1`.

---

## 14. Interaction Map

*   **Tap Sparkline Card:** Triggers `.active-feedback` (scale down `0.96`, opacity `0.8`), routes to full-screen `ParameterDetail` view.
*   **Navigation Transitions:** Fade-in route transition.
*   **Modal Behavior:** Bottom-sheet slides up from bottom (`translateY(100%)` to `0`) with a visible drag-handle.
*   **Gesture Interactions:** Horizontal swipe on carousels uses native CSS `snap-mandatory snap-center`.

---

## 15. Motion System

*   **Tap Feedback (`.active-feedback`):** Duration `150ms`. Easing `ease-out`. Scale `0.96`. Opacity `0.8`.
*   **Sparkline Entry:** Duration `800ms`. Easing `ease-out`.
*   **Page Transitions:** Fade in duration `300ms`.
*   **List Staggering:** Delay children by `50ms` each on initial mount.

## 16. Visual System

    *   Surfaces: Pure `#FFFFFF` (Light) or `#1C1C1E` (Dark).

# 🛑 PRODUCTION GUARDRAILS & STANDARDS

---

## 18. Design Guardrails (STRICT RULES)

The following practices are **STRICTLY PROHIBITED** on the mobile render tree:

*   **NO font size below 16px:** Any input field or body text below 16px triggers iOS auto-zoom, destroying the native feel. Smaller sizes (`12px`, `13px`) are ONLY allowed for non-interactive labels/subtext.
*   **NO multi-column layouts:** Except for strict 2-column micro-grids (e.g., Min/Max stats). The primary layout must be a vertical stack or a horizontal scroll (`snap-x`).
*   **NO overflowing elements:** Content must strictly fit within the viewport width (`100vw`). `overflow-x-auto` is only permitted when combined with `snap-x` and `hide-scrollbar`.
*   **NO heavy shadows or blur:** `backdrop-filter: blur()` and heavy `box-shadow` are strictly forbidden on mobile to guarantee 60fps rendering. Use solid surfaces (`#1C1C1E` or `#FFFFFF`) instead.
*   **NO Recharts or Canvas:** Data visualization on mobile must strictly use pure SVGs (`MobileSparkline`).

---

## 19. UI States (CRITICAL)

Every screen and component must account for the following states:

### Loading State
*   **Skeleton Layout:** Do not use spinners for page loads. Use matching structural skeletons with a soft background pulse.
*   **Animation Behavior:** `animate-pulse` with an opacity range of `0.3` to `0.7`. Duration `1.5s` infinite.

### Empty State
*   **Messaging:** Clear, actionable, and non-technical. (e.g., "Upload your first report to see your health trajectory" instead of "Data array empty").
*   **Illustration Style:** Single, centered, muted SVG icon (e.g., `Activity` or `FileText` from Lucide) sized at `48px`, utilizing `text-gray-400`. No complex vector art.

### Error State
*   **Retry Interaction:** Always present a clear, 44x44px tappable "Try Again" button below the error message.
*   **Visual Tone:** Do not use aggressive red backgrounds. Use soft tinted surfaces (`bg-red-50 text-red-700` in Light, `bg-red-500/10 text-red-300` in Dark) with a subtle alert icon.

---

## 20. Navigation System

### Bottom Tab Structure
*   **Exact Tabs:** Home (Dashboard), Reports (Upload/List), Timeline (History), Profile (Settings). Maximum 4 tabs.
*   **Icons:** Lucide React icons. Stroke width `2`. Active state: filled or stroke width `3` with primary accent color.

### Navigation Hierarchy
*   **Back Behavior:** Deep links (e.g., Parameter Detail) must always have a top-left `<ChevronLeft>` back button. Do NOT rely entirely on the hardware back button.
*   **Modal vs Full-Screen:** 
    *   *Modal (Bottom Sheet):* Used for quick actions (Upload, Date Picker, Filter).
    *   *Full-Screen:* Used for heavy context shifts (Case Insights, Parameter Detail, Chat Interface).

---

## 21. Data Density Rules

*   **Max Cards per Viewport:** No more than 1.5 vertical cards or 2.5 horizontal cards should be visible simultaneously. Users must scroll to see more.
*   **Max Items before Pagination/Virtualization:** Lists exceeding 20 items must utilize `content-visibility: auto` or strict React window virtualization to prevent DOM bloat.
*   **Scroll vs Expand:** Do not use accordions for primary clinical data. Navigate to a new detail screen instead to maintain isolated context.

---

## 22. Accessibility System

*   **Minimum Touch Size:** ALL interactive elements (buttons, links, carousel cards) MUST have a minimum hit area of `44x44px`. Add invisible padding if necessary.
*   **Color Contrast Rules:** Text must meet WCAG AA standards. Muted text (`text-gray-500`) on white is the absolute lowest permissible contrast boundary.
*   **Text Scaling Behavior:** Use `clamp()` for headings. Body text must remain readable when the user's OS font size is increased up to 150%.
*   **Motion Reduction Fallback:** Respect `prefers-reduced-motion`. Disable stroke drawing animations and spring scaling if the user has disabled OS animations.

---

## 23. Performance Constraints

*   **Max Animation Duration:** Standard UI transitions must not exceed `300ms`. Complex SVG draws are capped at `800ms`.
*   **Allowed Animation Types:** Animate ONLY `transform` and `opacity`. Strictly NO animation of `width`, `height`, `top`, `left`, `margin`, or `padding` due to layout recalculation costs.
*   **Rendering Limits:** Re-renders must be strictly controlled. Context subscriptions that update frequently (e.g., scroll position) must be decoupled from heavy component trees.
